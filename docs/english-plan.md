# 영어 넣기 계획 (2026-10-10 결정: 데모부터 영어를 넣는다)

> 이 문서는 계획만 적은 것이다. 실제 작업은 사용자가 "영어 시작해 줘"라고 할 때 1단계부터 하나씩 한다.

## 왜 지금 정했나
- 스팀 이용자 중 한국어 사용자는 적다. 한국어만이면 데모를 볼 사람이 크게 준다.
- 글이 늘수록 옮기는 일도 는다. **여름 대사가 더해지기 전에** 구조를 만드는 게 가장 싸다.

## 지금 글이 있는 곳 (2026-10-10에 셈)

| 어디 | 파일 | 글 줄 | 한글 글자 |
|---|---|---|---|
| 데이터 `.tres` (손님 대사·사연·레시피·노트·안내·계절) | 76개 | 약 980줄 | 약 23,300자 |
| 장면 `.tscn` (버튼·제목 글) | 40개 | 약 170줄 | 약 1,800자 |
| 스크립트 `.gd` (상수로 둔 안내 글, `%s` 넣는 글) | 57개 | 약 330줄 | 약 4,800자 |
| **합계** | | **약 1,500줄** | **약 30,000자** |

- 한국어 조사 도우미(`scripts/ui/korean.gd`): 을/를·이/가·와/과 9곳, 낱말 단위 줄바꿈 9곳.
- 세이브에는 글이 아니라 id 만 들어 있다 → **언어를 바꿔도 세이브는 그대로** 이어진다 (주인공 이름만 글).

## 방법 (가장 작게 바꾸는 쪽)

Godot 에 이미 있는 번역 기능(TranslationServer, `tr()`)을 쓴다. **한국어 원문을 그대로 열쇠로** 쓴다.
- `.tres`·`.tscn`·`.gd` 안의 한국어는 지금처럼 둔다 (데이터 구조를 안 바꾼다. 디자이너·개발자가 지금처럼 한국어로 쓴다).
- 번역 파일 하나(`translations/en.po`)에 "한국어 원문 → 영어"를 모은다.
- 화면에 보여 주기 직전에 `tr()` 을 거친다. 버튼·라벨 같은 장면 글은 Godot 이 자동으로 번역한다 (auto translate).
- 번역이 없는 줄은 한국어가 그대로 나온다 → 번역이 덜 돼도 게임이 멈추지 않는다.

## 단계 (한 번에 하나씩, 단계마다 봇 검증)

1. **글 뽑기 도구** — `tools/i18n/extract.py`: `.tres`·`.tscn`·`.gd` 에서 한국어 글을 모아 `translations/messages.pot` 로. 새 글이 생기거나 바뀐 글을 알려 준다.
2. **화면 연결** — 데이터 글을 보여 주는 곳(대화창, 평상, 메뉴판, 노트, 수첩 등)에 `tr()`. `%s`·`{name}` 넣는 글은 번역한 뒤에 채운다.
3. **조사·줄바꿈** — 영어일 때 `Korean.object_particle` 등은 빈 글을 돌려주고, 줄바꿈은 낱말 단위 그대로 쓴다. 글자 수가 길어 넘치는 곳 점검.
4. **설정에 언어 고르기** — 설정 메뉴에 한국어/English. 처음 켤 때는 컴퓨터(스팀) 언어를 따른다. 설정 파일에 저장 (세이브와 따로).
5. **글꼴** — 본문 픽셀 글꼴(MaruMinyaHangul)과 제목 글꼴(교보 손글씨)에 영어 글자가 있는지, 영어로 보기 좋은지 확인. 필요하면 영어 전용 글꼴을 더한다 (이용 조건 확인).
6. **번역하기** — 영어 번역 초안은 Claude 가 만들고, 이름(할매식당, 손님 이름, 요리 이름)은 따로 목록으로 먼저 정해 사용자가 고른다. 말투(토끼는 수줍게, 암탉은 수다스럽게)를 살린다.
7. **영어로 봄 한 판** — 자동 플레이(bot·pad)를 영어로 돌려 넘치는 글·안 옮긴 글을 찾는다. 스팀덱 화면(1280×800)도.

## 정해야 할 것 (6단계 전에)
- 영어 게임 이름 (예: Granny's Kitchen in the Woods — CLAUDE.md 에 적힌 이름)
- 손님·요리 이름을 옮길지, 한국 이름을 살릴지 (예: 김밥 → Gimbap)
- 번역을 사람(원어민)이 마지막에 봐 줄지

## 하지 않을 것
- 데이터 구조를 언어별로 나누기 (`.tres` 를 언어마다 복사) — 고칠 곳이 두 배가 된다
- 영어 말고 다른 언어 (영어가 자리 잡은 뒤에)
